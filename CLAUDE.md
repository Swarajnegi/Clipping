## The edit in five stages

1. **Source-only proof.** Find fluent, natural speech with a spoken hook in the first three seconds, development, and a satisfying complete payoff. Favor reflective, specific insights that fit thought.palace. Search beyond any one show and follow the brief's runtime. Check context, original source, reuse basis, actual FPS and source quality. Give the owner a playable proof with original audio, exact source ranges and a second-by-second opening note. Wait for passage approval.
2. **B-roll choices.** Map each spoken beat to a film/TV action, speaker hold, or card. Tell the owner the number of planned placements, library-covered slots, and distinct new excerpts to find. For each slot give the exact spoken cue, intended screen time, action, crop, usable source duration, playable option and source in/out, or a concrete sourcing request. Count one excerpt once if it serves multiple slots. Mark which slots could change when music is picked. Wait for shot choices.
3. **Song timing, when requested.** Offer two or three ranked exact recordings with track/artist/version, link, excerpt start and end, and edit offset. Verify the actual timing reference and label YouTube Sound picker availability if unverified. Ask the owner to choose. Map the selected recording's audible beats, stops and melodic changes to native frames. Reconcile the shot count and return only changed slots for approval. When the owner handles music independently or requests no music, proceed on speech timing. A timing audition stays in Working. The default delivered MP4 carries dialogue and intentional SFX, with the song added by the owner in YouTube Sound.
4. **Lock picture, transitions and SFX.** Assemble a caption-free preview with sound. Look for the first meaningful picture change on the earliest natural beat, often within the first two seconds. Use mostly hard cuts, stable speaker framing, dialogue-matched cutaways, and short connected actions when the pace earns them. Inspect the final crop and both sides of every boundary. Give the speaker room for a turn or payoff. Align a cleared sound to a motivated visual accent, such as the single shutter/white card at “and lastly” in Cavill. For a music-timed edit, each mapped beat needs a visual response or an intentional hold. A new shot, reaction or later caption emphasis can carry the beat.
5. **Caption last, then finish.** Use timed Inter Bold layers, occasional larger or heavier key words, and real Cormorant italic where it fits. White Difference applies to every spoken word by default, with the approved clean, shadow-free finish. Choose a whole-phrase layout for each shot. Keep faces, action and all glyphs clear. For a top-to-bottom stack, retain earlier lines while subsequent lines arrive below. Use true keyframed foreground masking when needed, and check that complete words remain legible through the motion. If the owner asks for frame review, supply the requested numbered frames and wait before encoding the final. Verify with sound, then deliver the video, cover, short posting copy and confirmed song cues if applicable.

Approvals already supplied in the brief count. A material change to speech, shots or song timing reopens the affected decision. Match B-roll to the actual meaning and emotion of the line. Compare the visual sequence without sound, then against dialogue. A generic door, cropped-away subject, random back view or a recognisable title alone rarely communicates the intended action.

## Local runtime and commands

Use native PowerShell and the existing Clipping venv. These variables are shell-local. Source the parent environment in each fresh shell that runs media work.

```powershell
Set-Location -LiteralPath 'D:\J.A.R.V.I.S\Clipping'
. 'D:\J.A.R.V.I.S\.runtime\environment.ps1'
$ClipPython = Join-Path $PWD '.venv\Scripts\python.exe'
$ClipGuard = Join-Path $PWD '.agents\skills\viral-shorts\scripts\run_guarded.ps1'
& '.\.agents\skills\viral-shorts\scripts\check_environment.ps1'
if ($LASTEXITCODE -ne 0) { throw 'Read the Clipping preflight diagnostic.' }
```

Run every heavy local media stage through the existing Windows guard. Pass an executable path and an argument array. The guard controls one heavy stage at a time, with current mains, CPU, RAM, GPU and thermal checks. Admission currently requires 4 GiB available RAM. A fast fan or successful earlier run cannot establish admission. Leave JARVIS services, pause state, watchdog, safeguards and caches alone. For deferred runs, read the diagnostic and use the [guard instructions](.agents/skills/viral-shorts/SKILL.md#mandatory-resource-guard--every-invocation-and-heavy-stage). For completed runs inspect `.runtime/guard/<run-id>/result.json`, `stdout.log` and `stderr.log`. Require worker success and confirmed cleanup before accepting the result. A GPU failure does not trigger automatic CPU rendering.

Bind `$VideoInput`, `$WorkId`, `$CandidateRanges`, and `$ClipsJson` from the actual brief and outputs. The commands below are individual stages.

```powershell
# Metadata-only library search. Decoding and motion review still use the guard.
& $ClipPython 'scripts/movie_library.py' search 'trying again after failure' --min-duration 5 --limit 12
# Acquire and analyse the original. $WorkId should identify the same source.
& $ClipGuard -Mode Run -Workload Gpu -FilePath $ClipPython -ArgumentList @('scripts/prep.py', $VideoInput, '--work-id', $WorkId)
# Inspect candidate windows. $CandidateRanges is source seconds, e.g. '12.5-24,60-75'.
& $ClipGuard -Mode Run -Workload Cpu -FilePath $ClipPython -ArgumentList @('scripts/sheet.py', $WorkId, $CandidateRanges, '--frames', '8')
# Build a proof from a proof spec, or a final from the approved final spec.
& $ClipGuard -Mode Run -Workload Gpu -FilePath $ClipPython -ArgumentList @('scripts/build.py', $ClipsJson, '--output-scale', '1')
```

For a source-only proof set `captions: false` and omit intro, hook text, cutaways, music and transition cues. For a caption-free picture proof include approved picture and SFX cues. If a proof needs a custom frame, use `referenceEdit.profile: "restrained"` with explicit geometry and `captions: false`; the builder requires real layers for the final editorial profile. Keep the source and final specs separate. `build.py` stages in `work/<id>`, `public/clips/<id>` and `out/<id>`. Keep editable specs and QA under the project in Working. Use scale 2 for 2160×3840 finishing where appropriate. Prefer compatible native 4K and preserve source FPS. Explicitly report any lower-resolution master and upscale. The usual design is a 980×980 rounded square centred on a black 1080×1920 logical canvas. Reframe per shot, and use wider framing when the passage benefits.

## QA, delivery and examples

- Inspect the opening at phone size, both sides of every cut, every fully revealed caption group, each transition/SFX cue, all mask overlaps and the ending. Listen through the complete cut and record the actual reviewer and coverage. Report any unavailable playback or timing check. Check full decode, frame count, native FPS, dialogue continuity and source branding. Compare audio packet hashes/timestamps when the audio can be stream-copied. If effects change the mix, check dialogue timing and cue alignment. A full decode, frame sheet, ASR transcript and listening pass are distinct checks.
- Keep only the owner's approved branding, or leave the video unbranded. Track reuse for original speech, separate film/TV inserts, effects, cover assets and embedded music. A permission for the interview covers the stated interview. Record any separate reuse status accurately.
